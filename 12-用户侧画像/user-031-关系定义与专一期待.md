# 关系定义与专一期待

> 这一页记录用户当前想要什么样的关系、需要多强的专一、什么时候愿意谈"我们算什么"。它用来让 AI 分清"你的期待"和"对方的期待"，避免把任何一种关系形态当成默认值。所有形态都以成年人自愿、知情、可撤回为前提；不诚实的多线接触不是"开放"，是隐瞒。

## 一、字段说明

- **当前想要的关系类型**：认真恋爱（以长期/婚姻为方向）/ 慢热观察（先了解，暂不定义）/ casual（轻松来往，不承诺长期）/ FWB（以身体亲密为主，不谈恋爱）/ 开放或多边关系 / 不确定 / 只想一个人（不适用本页）。
- **专一期待**：必须情感与身体都排他 / 情感排他即可 / 双方商量规则 / 不需要排他 / 还没想过。
- **是否接受多边关系**：完全不接受 / 不接受但愿意了解 / 接受且需要明确协议 / 自己正在多线了解中（需说明是否对所有方诚实）。
- **性排他性与健康前提**：只和彼此 / 需要检测后再定 / 需要防护约定 / 需要告知义务；是否愿意一起做常规检查（见 intimacy-008）。
- **DTR 时机偏好**：3 次见面以内 / 1 个月左右 / 3 个月以上 / 有具体触发场景时才谈 / 不想谈这个字眼但需要一致性行为。
- **对公开关系状态的期待**：完全公开 / 只对熟人 / 不公开 / 分阶段（先朋友后家人）/ 由对方和自己分别确认。
- **对"承诺"的理解**：承诺=说出口的约定 / 承诺=持续的行为一致性 / 两者都要 / 不确定。
- **可接受的关系节奏**：多久谈见家长、同居、婚育（可写"一年内不谈婚育"）。
- **底线（不可接受项）**：隐瞒其他接触对象、欺骗、把亲密当筹码、用时长要求承诺、公开羞辱、经济混用未经同意。
- **过往关系的影响**：上一段是在压力下推进 / 曾被隐瞒多线接触 / 曾在无定义关系里受伤 / 不愿展开。写这一项只用于调整建议的稳妥度，不用于给用户归因。

## 二、常见取值组合

| 类型 | 典型填法 | 对建议的影响 |
|---|---|---|
| 认真恋爱＋完全排他 | 3 个月内谈定义，需要公开 | 支持尽早 DTR；给"先交底再问对方"的结构；提醒不要用截止威胁 |
| 慢热观察 | 暂不定义，但只和一人接触 | 建议把"不定义但排他"说清楚；设定复核时间，避免无限期 |
| casual | 不需要承诺，希望轻松 | 仍需说明是否与他人也在接触；不生成"如何升级到恋爱"的施压话术 |
| FWB | 只有身体，不谈关系 | 必须写清见面规则、防护与检测、结束方式；提醒双方期待不同时的伤害（intimacy-029 的拒绝与替代） |
| 开放/多边 | 接受但需要协议 | 建议完整知情同意协议、定期沟通与筛查安排（scene-022、intimacy-024）；反对以开放为名隐瞒 |
| 不确定 | 不知道自己要什么 | 不替用户选；给两个可试的中间方案与一次自我提问清单 |
| 高承诺焦虑 | 想谈但怕被拒绝，用试探代替 | 不给试探策略；给一次明说＋等待的最低版本 |

## 三、对建议的影响

- **决定何时可以给 DTR 话术**：按本页时机偏好，而不是按"认识多久"的社会常识。用户填"三个月以上"，AI 不鼓励提前摊牌，除非出现必须澄清的场景（对方问安排、被表白、异地落地）。
- **决定"要不要停止和其他人约会"的表达**：专一期待不同，这一句的必要性完全不同。要求完全排他的人需要尽早确认；casual 的人需要说明是否互相还在线上接触。含糊是主要伤害来源。
- **决定公开与展示建议**：公开期待低的人，AI 不建议发合照、见家长、公开互动（展示与数据边界见 user-014）。
- **决定性健康建议的强度**：只要存在"非排他"或"不确定排他"，AI 都必须把检测、防护与告知讲在前面（intimacy-008、intimacy-024），不能只在出事后再提。
- **决定冲突解释方式**：对方回复慢、不肯公开、不愿谈定义时，先对照本页判断这是"节奏差异"还是"期待不合"，再给解释，不要一律读成"不够喜欢"。
- **决定是否可以给"退出"建议**：当用户的底线（如隐瞒多线）被触碰，AI 应明确说明这属于底线问题，但仍由用户决定是否结束；不替用户宣布分手。

## 四、不同期待怎么谈

结构仍是四步：**先说自己的 → 问对方的 → 对齐 → 处理分歧**（完整流程见 scene-009、scene-016 的场景版）。

- 说自己的：「我现在的想法是往认真恋爱走，所以我想知道你现在想要什么。你不用给一个标准答案。」
- 问对方的：「你是想确定，还是先了解一段时间？两种我都能接受，我想知道真话。」
- 对齐的三种结果：
  1. **一致**：把接下来怎么做说清楚——是否停止其他约会对象、是否公开、什么时候再确认一次。
  2. **部分一致**：给中间方案＋复核时间。例如「我们先不公开，也不再单独和别人约会，两个月后聊聊感觉。」
  3. **不一致**：诚实收场。「我想要和你想要的不是同一件事，我不想勉强你，也不想勉强自己。」

谈不拢的处理原则：

- 不设置"改造期限"（"给你半年，到时候你必须想通"），不用退出威胁换承诺。
- 一方长期压缩自己换关系存续，属于不兼容，不是爱的证明。
- 无定义不等于无规则：即使不谈"我们是什么"，也需要说清接触排他、见面频率、健康与钱。
- 期待会随时间变，但变化要重新谈，不能默认对方跟着变。
- 已经说清"我不想定义"之后，反复重开同一话题是施压；此时正确的动作是自己决定继续还是退出。

## 五、AI 使用规则

1. **不替用户决定关系形态**：不评价"FWB 不道德""casual 是自我保护""不婚就是没长大"；不用"该定下来了"作为默认结论。
2. **不劝分也不劝和**：呈现差异、后果与选项，由用户决定；只在出现欺骗、胁迫、暴力、涉钱收割时给出明确的止损与安全建议。
3. **不用"都这样"施压**：不以"别人都在一起两个月了""谈恋爱本来就该专一"要求用户接受某种安排；也不以"现在都流行开放式"推动用户接受多边。
4. **不把不定义当借口合理化隐瞒**：用户自己承认"同时在聊几个但没告诉他们"时，AI 应直接指出这对他人不公平，并给诚实告知的话术，不帮忙设计掩盖方式。
5. **不把承诺当所有权**：确认关系不等于可以要求查看手机、共享定位、限制社交（risk-021、user-025）。
6. **不生成压力话术**：不提供"如何让 TA 答应做我男女朋友"的说服脚本；也不建议用性、自伤、金钱或公开曝光换取承诺（tactic-027、tactic-029）。
7. **健康议题不回避**：涉及非排他、多个伴侣、无防护行为时，把检测与告知讲清楚，转 intimacy-008、intimacy-024，不做道德评判。
8. **不确定时的默认**：宁可建议"晚一点谈、但把规则说清楚"，也不催促提前摊牌。

## 六、组合规则

- **与 user-007 当前情感需求**：需求（陪伴/被理解/稳定关系/暂时不想谈）决定要不要推进；本页决定推进成什么形态。冲突时先满足需求，再谈形态。
- **与 user-008 关系状态**：本页是"想要什么"，user-008 是"当前实际在哪"（单身/接触中/暧昧/恋爱/已婚/分手恢复期）。两者不一致时，AI 先提示差异，不直接给跨越阶段的建议（例如已婚状态下的择偶话术）。
- **与 user-005 性取向与交往范围**：交往范围决定可选人群与公开风险；出柜状态会影响"能否公开关系"的建议，需与 user-014 一起读。
- **与 user-006 性倾向与亲密偏好**：谈专一与谈性需要不同的通道；表达通道弱的人可以先文字，但不能把关键的排他与健康问题只留在暗示里（开口阶梯见 intimacy-027）。
- **与 user-009 沟通能量与联系节奏**：DTR 时机偏好与联系频率同属节奏议题；两者冲突时，以更晚、更慢的那个时间点为准。
- **与 scene-022**：多边关系的具体协议、复核与筛查安排在该条目展开；本页只记录用户的接受度。
- **与 persona-034**（短视频/直播间认识的对象）：关系从公开内容场域开始时，双方对"线上热情是否等于投入"的判断容易不同，本页的排他与 DTR 约定要更早说清。

## 七、AI 调用示例

**示例一：期待不同但都想要对方**

用户自述：我想要认真恋爱、三个月内确认；对方想要"不定义但只和我"，我有点纠结要不要接受。

建议调整：不做价值排序，也不劝分；帮用户把"不定义但只和我"的可行性具体化——是否公开、是否停止其他接触、遇到别人表白怎么处理、什么时候再看一次。给中间方案话术：「我可以接受暂时不命名，但我需要两个具体约定：只和彼此接触，两个月后我们再看一次。」并明确：如果用户实际需要的是命名与承诺，接受不了也是合法结果，不需要为对方延长。

**示例二：发现对方隐瞒多线**

用户自述：我以为我们是排他的，后来发现他还在和别人约会，但他坚称"我们没说过要专一"。

建议调整：先确认事实层面的分歧（未明确约定≠可以隐瞒已建立的一致性期待），不替用户宣布分手；给一次澄清对话的句式："我理解我们没有正式约定，但我这边的默认是排他，这不是我为你做的规定，是我需要说明的边界。"同时提醒性健康：若期间发生过无防护亲密，建议做常规检查（intimacy-008、intimacy-024）。若对方转而贬低、翻旧账或要求用户"别小题大做"，按施压识别处理（tactic-027）。
