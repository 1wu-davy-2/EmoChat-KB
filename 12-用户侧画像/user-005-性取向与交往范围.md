# 性取向与交往范围

> 这一页帮助 AI 理解用户可能愿意与谁交往、在什么范围内感到安全，不用于猜测或评判任何人。性取向以用户自述为准，不假定、不矫正、不猎奇。

## 取值与含义

| 取值 | 通常指 | 交往范围提示 |
|---|---|---|
| 异性恋 | 主要被不同性别者吸引 | 不等于必须按传统性别角色相处 |
| 同性恋 | 主要被同性别者吸引 | 公共场合的安全与可见度需单独评估 |
| 双性恋 | 可被多种性别吸引 | 不是"阶段"，也不是"花心" |
| 泛性恋 | 吸引力不完全受性别限制 | 以具体的人为准，不套用二元框架 |
| 无性恋 | 性吸引很少或没有 | 可能有浪漫吸引；浪漫取向与性取向分开谈 |
| 酷儿 | 拒绝或不符合传统分类 | 尊重用户自己的用法，不替其定义 |
| 不确定 | 仍在探索 | 不需要急着贴标签，允许变化 |
| 不愿透露 | 用户选择不填 | 不追问、不推断，按中性处理 |

"交往范围"指用户愿意认识的人群、场合与公开程度，不是对某类人的挑选标准，更不代表对方理应接受任何接近。

## 各自身份下的注意点

- **异性恋**：也可能面对性别角色期待、催婚与经济压力；不因"主流"就忽略边界。
- **同性恋**：出柜与否是个人决定；公共场合的亲密程度、见家长、职场公开都需先确认安全与同意。
- **双性恋**：常被误解为"还没选好"或"更容易出轨"；不把刻板印象写进建议，也不要求用户自证。
- **泛性恋 / 酷儿**：称呼与身份用语以用户自述为准；不纠正、不追问"到底喜欢哪种"。
- **无性恋**：不把低性欲当冷淡、病或需要治疗；亲密关系可以包含陪伴、浪漫与身体边界协商，见 user-006。
- **不确定 / 不愿透露**：提供探索空间，不催结论；建议中避免默认异性恋脚本。

## 出柜安全

- 出柜的时间、对象、方式由用户决定；AI 不劝"勇敢一点"，也不把公开当成关系诚意的证明。
- 先评估安全：居住地、家庭经济依赖、工作环境、法律与社会支持；必要时先建立支持网络。
- 不替用户向家人、同事或对方出柜；不代发消息、不暗示、不在公开平台提及。
- 关系公开前先确认：哪些人能知道、哪些场合不能提、照片能否发布、紧急联系人如何设置。
- 若遭遇歧视、威胁或暴力，优先安全与取证，可拨 110 或联系当地公益机构；见 risk-021。

## 隐私与社群

- 交友软件与社群既是支持来源，也可能混入诈骗、猎奇和"矫正治疗"陷阱；不轻信"帮你确认取向""介绍圈子"的付费服务。
- 不向陌生人透露住址、单位、证件、财务信息；私密影像风险见 risk-012、risk-016。
- 不把用户的性取向写进可被他人看到的档案；共用设备时提醒用户清空或加密。
- 社群内的称呼、黑话与规则不统一，以具体社群的公开说明为准，不替用户承诺"圈内都安全"。

## AI 使用规则

1. 不默认用户是异性恋；需要时用中性问法："你愿意说说你通常会被什么样的人吸引吗？不想说也完全可以。"
2. 一次只问一项，先说明用途与保存方式，再询问性取向或出柜状态。
3. 不把性取向当猎奇话题，不追问身体细节、恋爱数量或"怎么发现的"。
4. 建议中不出现"试试就知道""掰直/掰弯"等说法；性取向不是可以被说服改变的任务。
5. 画像用于调整建议，不用于给他人贴标签或施压；也不替对方出柜。
