# 线上展示与隐私边界

> 这一页记录用户在公开网络上的"可被看到程度"，以及愿意让别人看到什么。它用来防止 AI 默认"发条合照宣布一下""开定位打卡"这类建议，也用来判断某个推进动作会把用户暴露到什么位置。它与 user-014 互补：user-014 记录关系公开与数据留存原则，本页记录平台展示层面的具体边界。

## 一、字段说明

- **是否露脸**：可发正脸 / 只发侧脸背影 / 只发物品与文字 / 从不出镜 / 分平台（例如 B 站露脸、抖音不露）。
- **是否公开位置信息**：可写城市 / 只写区域 / 可带店铺定位 / 关闭所有定位 / 发布延迟（离开后再发）。
- **是否公开工作、学校、单位**：可写 / 只写行业 / 不写 / 明确禁止（同事或学生会看到）。
- **是否公开关系状态**：完全公开 / 只对朋友公开 / 只对家人公开 / 完全不公开 / 部分公开（发合照但不写身份）。
- **是否接受被拍**：可被拍但需本人确认后才发 / 可拍不可发 / 不接受被拍 / 看场合（家庭聚会可、公开场所不可）。
- **是否接受对方发布合照或聊天截图**：可发合照 / 只发不含第三人的照片 / 不发聊天截图 / 一律需事先同意。
- **是否发私密影像**：不发（默认）/ 曾经发过 / 考虑中 / 不愿讨论。任何取值下 AI 都不催、不建议、不索要。
- **私信与互动边界**：接受陌生人私信 / 只接受熟人 / 接受被 @ / 不接受被公开 @ / 关闭评论 / 会回复陌生同好 / 不回复陌生人。
- **账号结构**：单账号实名 / 工作号与私人号分开 / 有小号但不给人 / 只看不发。
- **可识别信息**：住址、门牌、车牌、工位、孩子学校、常去的健身房——是否在任一处出现过。
- **关系结束后的处理**：保留动态 / 删除合照 / 拉黑并清空 / 不删但设为私密 / 需要安全退出方案。

## 二、常见取值组合

| 类型 | 典型填法 | 对建议的影响 |
|---|---|---|
| 高曝光 | 露脸、带定位、公开关系状态 | 提醒公开内容不可撤回；分手后的处理要提前有数（risk-037） |
| 半匿名 | 不露脸、只写城市、内容偏兴趣 | 不要把"露脸认证"当信任前提；线上核验改用语音/视频（不要求证件） |
| 职业受限 | 不写单位、同事会刷到、公开互动需谨慎 | 不安排在公共平台互动；不建议带定位打卡；约会场所避开本单位活动范围 |
| 未公开关系 | 完全不发、不当着家人提 | 不替用户公开、不做"惊喜宣布"；合照与共同出行需按用户边界处理 |
| 谨慎接收方 | 关闭陌生人私信、不开评论 | 建议用户不要为了推进关系去绕开自己设的边界；也不建议以"解开限制"考验别人 |
| 曾被泄露 | 曾被截图转发、被前伴发布过内容 | 优先安全与取证；所有建议默认"信息可能被第三方看到"；提供下架与求助路径 |

## 三、风险提示

- **人肉与名誉攻击**：住址、单位、学校、车牌、常去地点、孩子信息一旦出现在公开内容里，可被拼出日常路线。被公开 @、被截图挂到群里或被"避雷帖"针对时，按 risk-027 处理：保留证据、不要自证、走平台与法律路径（12348 法律咨询）。
- **跟踪与线下风险**：定位打卡、健身房照片、家门口的合照都会暴露路线。进入一段新关系时，避免一次给出可拼合的完整信息（住址＋单位＋常去时间）；见面安全动作见 risk-014。
- **报复性私密影像**：任何发出的影像都可能被转发；删除不等于消失。若已被威胁或以发布为筹码要挟，立即停止给付、保留原对话与账号信息、拨 110，路径见 risk-037；同时不要独自承担羞耻，联系可信的人或妇联 12338。
- **裸聊敲诈与 AI 合成**：陌生关系里的"视频聊点刺激的"往往是录屏要挟的入口；合成影像可被用来伪造内容（见 risk-016、intimacy-006）。已经发生就停付、不继续对话、保存证据报警。
- **诈骗**：过度热情的陌生人＋很快转到私聊小号＋涉及钱、投资、验证码、代充，一律按收割路径处理（risk-031、risk-034）。
- **平台设置会变**：不要假设"仅好友可见"绝对安全；共同好友、截图、算法推荐都可能扩散。每半年或在换工作、搬家、进入或结束关系后复核一次本页。

## 四、对 AI 建议的影响

- **公开度低**：不建议在公共平台互动、不安排高曝光场所、不主动提出见家长或公开宣布；提醒合照与定位的暴露风险。
- **不接受被拍/被发**：所有"发个合照确认关系"的建议直接排除；给替代动作（只给自己看、不发平台）。
- **不发私密影像（默认）**：不生成、不建议、不评价；被索要时给一句明确拒绝＋留证提醒，例如「这种我不发，也不希望再被提。」
- **私信边界**：用户不接受陌生人私信时，不设计"绕过去"的路径；用户自己想主动私信别人时，只给带理由与退出口的写法。
- **职业敏感**：涉及同事、客户、学生可见的平台，建议偏保守；不把公开互动当作感情推进的证据。
- **核验方式的替代**：需要用身份建立信任时，用"可当面核验的公开场景"（视频通话、朋友在场、工作时间自然可见）而不是要求证件、住址或工牌照片。
- **求助提示保留**：出现被曝光、被要挟、被跟踪的描述时，AI 先给安全动作与报警路径，再谈关系议题。

## 五、AI 使用规则

1. **不鼓励发私密影像**：不以"信任我就发""别人都发"作为论据；不提供"如何说服对方发"的话术；用户主动表达想发时，AI 只说明不可撤回性与风险，不协助起草内容。
2. **不教规避平台**：不提供拆字、谐音、图片藏号、绕过审核、绕开私信限制、伪装身份的任何做法。
3. **不鼓励人肉对方**：不建议跨平台搜索、扒早年动态、找共同朋友打听、开小号查看主页；这类行为本身有法律与安全风险（risk-015、risk-027）。
4. **不替用户公开**：不在建议里假设"应该发条动态确认关系"；公开与否按用户填写值，且需双方各自同意。
5. **最小收集**：不要求用户提供身份证号、住址、单位、车牌、学校、孩子信息；对话里出现时不复述、不建议保存，敏感项默认不跨会话引用。
6. **不把暴露度当信任指标**：不认为"不肯发合照=有别人"，也不认为"肯开定位=真心"；这类要求容易滑向控制（risk-021）。
7. **不做道德评判**：露脸、发跳舞视频、开直播都不构成"随便"或"暗示可搭讪"；被骚扰的责任在骚扰者。
8. **未成年信号**：出现未成年信号时，所有社交向与展示向建议停止，只保留安全与求助路径。

## 六、组合规则

- **与 user-014 隐私与安全偏好**：user-014 定原则（默认本地保存、敏感项可留空、AI 记忆范围），本页定平台层面的具体动作。两页冲突时以更保守的一方为准。
- **与 user-015 时间精力与社交预算**：习惯决定"在哪里发生、能投入多少"，本页决定"可以被看到多少"。建议跨平台转移动作前，两页一起读。
- **与 user-025 社交边界与异性朋友观**：点赞、评论、公开互动属于双方共同边界，需分别确认，不能以一方意愿代替双方。
- **与 user-009 沟通能量与联系节奏**：联系变密不代表可以提前公开或提前交换可识别信息；线上暴露度的提升应有独立同意。
- **与 06 板块**：涉及影像、定位、泄露、跟踪、要挟时，风险优先于关系议题，一律先给安全动作（risk-012、risk-016、risk-027、risk-037）。

## 七、AI 调用示例

**示例一：被要求发合照**

用户自述：对象想发我们的合照到朋友圈，我这边同事都能看到他，我不想发，但他说不发就是不想公开。

建议调整：明确这是展示边界，不是忠诚测试；给一句边界话术："我愿意让关系存在，但我不接受用公开方式换信任。我们可以先只让各自的朋友知道。"同时提醒双方各自同意，不替任何一方决定；若对方升级为查手机、要求共享定位或冷战施压，按控制与安全风险处理（risk-021、user-014）。

**示例二：刚认识就要求视频"验证"**

用户自述：网友要求我发手持身份证的自拍才肯继续聊，我有点不安，但不想被说防人。

建议调整：拒绝是正当的，不提供证件类核验的替代话术；给出替代方案（一次十分钟视频、约在公开场所见面）；提醒对方若坚持索取证件、住址、私密影像，按诈骗与侵犯隐私路径处理（risk-031、risk-012）；AI 不协助生成或转发任何含可识别信息的影像。
